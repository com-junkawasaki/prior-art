Each document below is a defensive publication: it is published solely to place its subject matter into the public domain of technical knowledge as prior art, so that a later filing directed to the same mechanism — or to an obvious variation of it — is met by an express written disclosure. No patent protection is sought by the author for any subject matter described.

Every section is written as problem → mechanism → variants and generalizations. The variant enumerations are deliberate and broad: novelty is defeated by the mechanism, but obviousness is defeated only by having written the variation down.

Evidence, and its honest limits

  • Content fixing. The evidence manifest records each repository's commit and tree SHA-1. A git tree SHA-1 commits every byte of the tree by Merkle construction, so one 6.7 kB file fixes the complete content of all 31 repositories.
  • RFC 3161 time-stamp tokens over that manifest and over the disclosure text. These are from FreeTSA, which is not an accredited timestamp authority in any jurisdiction. They are independently verifiable — not accredited. They are not equivalent to a token from Japan's 総務大臣認定タイムスタンプ, an eIDAS qualified timestamp, or China's 联合信任时间戳服务中心. Because the digests are already fixed, an accredited token obtained later covers the same digests and strengthens this bundle rather than replacing anything in it.
  • OpenTimestamps attestations anchored in the Bitcoin blockchain — the form of evidence Chinese internet courts have accepted (最高人民法院 online-litigation rules).
  • Software Heritage archival of the source repositories, and Internet Archive snapshots of these pages, so the record does not depend on the author continuing to host it.
  • What none of it proves. It proves the content was public on a date. It does not prove the content is novel, useful or correct, and it says nothing about whether the subject matter infringes anyone else's rights.

How to verify all of the above yourself — with openssl, git and curl, trusting nothing here.
